# 笔记同步助手与飞书首次接入

目标：用户把这个文件夹交给你后，由你检查、安装、配置和验证；只有微信操作、登录、授权等需要本人完成时才交给用户。使用用户自己的账号和密钥，不依赖制作者的电脑、笔记库或飞书表格。

## 本版范围

- 用户通过微信转发给自己的助手好友；Agent 读取用户指定的那一条笔记。
- 先检查飞书 CLI 是否已连接且身份正确；能用就复用，缺什么才补什么。
- 配置完成后主动邀请用户亲自转发测试；Agent 写入并读回，用户打开确认后设置增量定时同步，不默认批量导入历史。
- 在用户确认的位置建立自己的内容创作模板：选题池、视频剪辑、作品发布库、作品数据快照和原版视图/看板。读取 [记录规则](references/recording-rules.md)，按包内 assets/feishu-template.json 创建并保存实际 board.json；不依赖制作者的私有 Base 或个人字段。
- 日常“拉取一下”和定时任务执行 [同一轮同步流程](references/scheduled-run.md)。既有正文、图片、改写、高亮和版本完整保留；只依据实际动作更新拍摄/剪辑/发布状态。

## 交互方式

先说明：“我先检查飞书是否已经接好，能用就直接复用。之后带你在微信添加笔记同步助手、转发一条资料，我来读取并保存到你确认的飞书位置。需要你操作时，我会一次发齐这一组连续动作和图片，做完这一组再回复。”

先检查已有环境，避免一次问十个问题。每次以一组连续动作交接：说清现在做到哪，一次列齐用户可以连续执行的操作与对应图片，给出整组完成标准和一次回复的内容。不要每点一个按钮就要求回来确认。命令由你执行；用户不必理解 API、OAuth、scope。

已授权接入所需的解压、环境检查、官方工具安装、写配置和只读验证由你推进，不逐条交给用户或重复询问。用户本人负责微信账号操作、提供个人密钥、登录及确认授权；系统确实要求本人操作时才交接，并说清具体按钮与完成标准。

优先用本包 `assets/official/` 的官方手机原图作当前步骤示例，`assets/screenshots/` 的网页截图作为补充，附官方原文链接。不能只给图片路径：有图片展示能力时把图显示在对话中，否则打开本地图片或官方页面。明确这是官方教程示例，不是用户的账号状态。截图时点和逐图说明见 [screenshots.md](references/screenshots.md)。页面变化时以官方当前指引和已安装 CLI 帮助为准。

每组用户操作都给出：按顺序列齐的具体入口与按钮、对应图片、整组预期结果、整组完成后的单次回复、官方章节链接。按 [整组发送示例](references/grouped-messages.md)组织实际消息；不能把参考文档的小节当作一轮一轮的确认点。没有对应微操作原图时如实标注图像覆盖范围，并查当前官方页面，不能制作仿真界面冒充截图。用户卡住或提问时，必须先读取 [help-and-official-docs.md](references/help-and-official-docs.md)，打开对应官方说明核对，再给出当前一步和可点击出处；不能只重复原来的概括指令。

用户操作需要等待时，把本组全部链接、二维码、连续操作和图片真正发送给用户，交还对话；用户整组做完回来后续接。只有遇到报错、必须本人授权、或后续链接依赖 Agent 取得前一步真实结果时才暂停；用户可以连续完成的扫码、登录、选账号、填写表单和确认按钮不能逐点拆轮。不要在用户还看不到链接时阻塞等待，也不要无限轮询。

## 网页获取失败时自动切换

通过网页口令接入时，网页读取工具打不开首页不等于下载站不可用。由 Agent 自动改用当前宿主的命令行 HTTPS 客户端（macOS/Linux 的 curl，Windows 的 Invoke-WebRequest 或 curl.exe）获取 `https://tools.minmin11538.cn/notehelper/install.md` 与同目录 `release.json`，下载完整 ZIP、核对字节数与 SHA-256 后安全解压。不要让用户换浏览器或手动下载；网页与命令行均失败时才报告实际错误。具体命令见在线 install.md；保留 TLS 校验，不忽略校验失败，不执行下载的远程脚本。

## 0. 先检查飞书，按缺失项继续

先读取 [feishu-setup.md 第 1 节](references/feishu-setup.md)，由 Agent 检查当前执行环境的 CLI、应用配置、登录有效性、账号与文档/云空间权限。WorkBuddy 等宿主只要能执行命令，就在其实际执行环境检查，不根据产品名称假定已经授权。

- 已连接且身份/所需权限正确：记录“飞书连接可复用”，跳过安装、创建应用及登录引导；实际目标访问在用户指定位置后验证。
- 只有登录过期：保留应用，仅补个人登录。
- 只有所需权限缺失：保留应用和现有连接，仅补本任务缺的权限。
- CLI 未安装：由 Agent 安装后继续检查；应用尚未配置且无合适可复用应用时，才走创建应用步骤。

命令失败先区分未安装、网络错误、权限或过期，不把所有失败归为“需要重建应用”。首次检查是只读的，不为试连接而创建测试文档。需要本人配合的步骤在独立工作目录就绪后，按对应小节展示。

## 1. 检查与就绪

**先用系统命令发现运行时，再运行 Python 脚本。** 优先使用宿主已经提供的 Python/Node，不因用户没配过就重复安装。

- Windows PowerShell：由你执行 `Get-Command py,python,python3,node,npm,lark-cli -ErrorAction SilentlyContinue`，再实际执行候选解释器的 `--version`；Windows Store 别名不算可用 Python。可用 `py -3 -c "import sys; print(sys.executable)"` 得到真正解释器路径。
- macOS/Linux：由你执行 `command -v python3 node npm lark-cli` 并分别核对版本；已知宿主的依赖发现能力优先于猜安装目录。
- 无 Python 时由你按[官方 Python 下载](https://www.python.org/downloads/)与[Windows 官方指引](https://docs.python.org/3/using/windows.html)选择当前支持版本和架构，完成下载、安装、重新发现及验证。Windows 官方安装管理器可由 Agent 用 PowerShell `Add-AppxPackage` 安装实际下载的 MSIX；系统确认或组织审批需本人时才交接。macOS/Linux 复用已有包管理器或按官方安装说明推进，不为本包另装整套开发工具。
- 无 Node/npm 时按[飞书接入](references/feishu-setup.md)补齐。安装后由你开启新命令会话或采用已核实的可执行文件路径处理 PATH，再验证；不要让用户自己找路径、抄安装命令。

由你记录解释器与本客户端的绝对路径。下文示例 `$TASK_PYTHON` 与 `$TASK_CLIENT` 是由 Agent 解析并设置的任务变量，用户无需填写；Windows 使用 `& $TaskPython $TaskClient ...` 的等价写法。只有文件读取、命令执行和联网能力可用的本地 Agent 才能自动完成；纯聊天工具应明确缺少能力，不能假装已安装。

```sh
"$TASK_PYTHON" "$TASK_CLIENT" doctor
"$TASK_PYTHON" "$TASK_CLIENT" workspace
```

doctor 不读取密钥正文、不联网、不安装软件。workspace 在当前用户 `~/.openclaw/notehelper-work/` 下新建本次专用目录，返回实际路径；由 Agent 将后续命令 CWD 切换到它。用户配置仍走自己的 NoteHelper 配置文件。

脚本始终用已记录的绝对路径调用，正文、动态二维码和临时文件只进入本次工作目录，**不以 skill 文件夹作运行目录**。重复测试重新运行 workspace，避免导出同名冲突；既有文件不覆盖。

本包由 Agent 直接读取执行，保留 scripts/references/assets 的相对结构；不向用户展开 skill 安装选项。需要重启后加载时，先给用户一段不含密钥的续接说明。

## 2. 笔记同步助手：用户取密钥，你配置

读取 [notehelper-setup.md](references/notehelper-setup.md)，按以下检查点推进：

1. 用户已有个人密钥：复用经用户指定的本机配置或环境变量，不让他重新申请。
2. 没有密钥：按整组示例第 1 组，一次展示参考 A1—A3、B1、B1a 的搜索、关注、发送、取密钥、添加好友与手机置顶操作及全部八张图片（新增操作示意与原有参考图）；不要只说“关注后发送 Obsidian，找到 API 密钥”。**这里借用官方获取密钥的入口，不要求安装 Obsidian。**
3. 微信转发是本包唯一的资料入口。第 1 组完成添加好友和置顶；密钥由 Agent 保存校验后，第 2 组一次展示参考 B2—B5 的打开资料、转发、选择收件人、发送及查看通知的全部动作和图片。不要把教程示例里的好友二维码当成用户的绑定二维码。
4. **默认支持用户在 Agent 对话框提供密钥**。第一次请求前简短说明：“你可以直接把个人密钥发在这里，我来保存和验证；它会进入聊天记录，并由当前 Agent 服务处理，工具记录也可能保留输入。”用户选择或已经主动提供后直接接着做，不再要求他开终端、运行命令或重复发送。

```sh
"$TASK_PYTHON" "$TASK_CLIENT" configure --stdin
```

由你通过宿主的子进程 stdin 输入通道传入一行密钥，不能将密钥作为命令行参数、写进 .py/.sh/.ps1 临时源码或再打印出来。宿主只有交互执行通道时，启动不带 --stdin 的 configure，等隐藏输入提示出现后由你将已收到的密钥写入该进程输入；用户仍无需操作后台终端。不能隐瞒聊天/工具记录的留存，也不能声称程序不回显就代表平台不记录。

配置写入用户本机 `~/.openclaw/notehelper.json`。已有文件默认保留；只有用户确认换钥匙才 `--replace`。用户选本机隐藏输入时，由你先打开他可操作的终端/宿主安全输入入口，使用同一 configure 的隐藏提示；确实无法打开才给对应系统的最短人工兜底，不能把后台 PTY 冒充可见窗口。完整交接见 [notehelper-setup.md](references/notehelper-setup.md)。

5. 由你执行只读连通检查：

```sh
"$TASK_PYTHON" "$TASK_CLIENT" check
```

返回 `ok:true` 才能说密钥有效。返回 0 篇表示库为空，不代表接入失败。403/1010 先检查客户端 UA；401 检查密钥；402 交给用户自行决定权益/积分，不代付。

本包客户端沿用官方 NoteHelper Skill 公布的接口读取同一个笔记云库；不再让用户另选安装方式。官方来源见参考 D。

## 3. 读取微信转发的指定资料

请用户按整组示例第 2 组，连续完成 B2—B5，给自己已添加并置顶的助手好友转发一条愿意测试的资料；不要在选聊天或点发送后要求中间反馈。收到完成通知后一次告诉 Agent 标题关键词。只读搜索匹配标题，先看元信息，由用户确认目标条目后获取正文；不自行选择私密历史笔记。

```sh
"$TASK_PYTHON" "$TASK_CLIENT" search --query "用户给的标题关键词" --limit 10
"$TASK_PYTHON" "$TASK_CLIENT" search --query "用户给的标题关键词" --limit 1 --after "$SELECTED_AFTER" --id "$SELECTED_ID" --content --output "./selected-notes.json"
```

以上命令 CWD 为 workspace 返回的本次目录，`--output` 文件可能含用户正文。客户端还会拒绝导出进 skill 包内。一次返回不是全部云端历史；候选元信息响应有 `hasNextPage` 时用 `--after` 继续分页，并由 Agent 分配不同的导出文件名。正文读取前由 Agent 从已确认的元信息设置 SELECTED_ID 和 SELECTED_AFTER（条目的 result_after）；不是让用户填参数。保持同一 query，用 --limit 1 和该位置请求单条，并核对返回 ID。若不存在、返回多条或 ID 改变，客户端拒绝输出/导出；重新只读检索确认，不扩大正文范围。候选元信息可分页，正文只读选定一条，不继续翻页。不把摘要当全文。微信处理完成通知见截图 04。

本流程不调用 submit/progress，也不要求用户把新链接交给 Agent 提交解析。资料由微信入口处理，Agent 只读取已完成的指定笔记。只有简介时报告正文不完整，先按官方排障指引检查，不补交 API 任务。

## 4. 飞书：复用检查结果，只补缺失步骤

沿用第 0 步结果，按 [feishu-setup.md](references/feishu-setup.md)的分支执行，**不是从安装开始顺序重做一遍**。已就绪直接进入第 5 步。关键点：

- 已有可用 CLI/应用/登录态就复用；不默认新建应用、不改绑、不覆盖配置。
- 新用户由 Agent 安装 CLI 和 skills；按整组示例的第 3 组完成应用创建，再由 Agent 确认配置结果并生成真实 OAuth 链接，第 4 组完成个人授权。创建与授权各自组内全部连续操作、动态链接/二维码和示例图一次发齐；不为尚不存在的应用预造授权链接。
- 本版按实际缺失申请 `docs,drive,base` 业务域；缺具体 scope 再按实际报错补。不要默认 `--recommend` 或 `--domain all`。
- 配置链接由当前命令动态产生，原样展示，并由 CLI 生成二维码；截图 07/08 只作界面示例。
- OAuth 使用 `--no-wait --json` 分两轮完成，用户回复后由你执行 `--device-code` 续接，最后 `auth status --verify`。用用户身份访问个人资源。
- OpenClaw/Hermes 已有飞书插件时先核对绑定方式；不要为了本包另建一套冲突应用。

## 5. 建立模板、主动测试与用户验收

先读 [记录规则](references/recording-rules.md)。用户已授权接入时由 Agent 运行 scripts/feishu_template.py 创建用户自己的空白模板，保存回执和 board.json；不要将示例作者、个人账号或历史期次写入默认配置。已有合适目标先核对复用，不改原有个人业务表。模板仅包含通用选项及原版布局，初次拉取不自动改写或生成假拍摄记录。

首次测试也使用同一队列：用 sync_queue.py init --manual --board 实际board.json --config 实际配置 --target 实际文档位置 --timezone 实际时区，在独立固定目录建立基线。由 Agent 搜索定位用户指定的测试 ID，再按 scheduled-run.md 的 run-claim、select、next、文档创建/绑定、索引创建/绑定、双读回、complete、run-release 完整执行。已有 job 不重新 init。

先报告已核实的三项：NoteHelper 密钥只读校验、指定笔记读取、飞书用户授权。每项写“通过 / 未做 / 待用户操作”，附实际依据。

配置完成后主动发第2组转发指引，请用户亲自选一条资料测试，不只报告连接成功就结束。用户同意创建这篇测试文档并确认位置后，按已安装官方 `lark-doc` / `lark-base` skill 和共用流程执行创建、索引及读回。没有该 skill 时先装官方 skills，不靠猜参数凑命令。写入用户选定的那一条正文，保留来源；新建文档后记录 ID/URL，读回比对标题、正文段落和图片。导入没有图片或正文不全就明确说，超时先查是否已创建再决定重试。执行成功不等于用户已验收。

发送实际测试文档链接，请用户打开核对正文和图片。正文、图片和索引均读回通过后发送实际选题入口与文档链接。用户确认“测试正常”后，再进入第6步；未确认或正文/图片不完整时停在待测试，不能提前启用任务。

## 6. 测试通过后配置增量定时同步

读取并执行 [定时同步设置](references/scheduling-setup.md)，把用户测试、保存位置、频率/时区与新增范围合并交接；已有明确值不重复问。用户只确认测试、尚未指定频率时只补问缺项，不自行选择默认时间。首次基线跳过旧库，之后新增 ID 的批量读取与飞书写入必须包含在用户确认范围中。

复用第5步固定目录和已建立的基线，不另建手动/定时两套任务。旧版任务迁移先备份并核对已完成ID、文档URL与新索引映射，不重建或全量导入历史。由 Agent 用 scripts/sync_queue.py 维护任务。脚本复制运行时和 [每次运行指令](references/scheduled-run.md)，保存基线、按 ID 去重、pending/creating/created/done 状态和已核实的任务回执；不处理调度器创建，也不直接替代飞书 CLI。手动和定时 Agent 都执行同一 RUN.md，持有整轮运行锁，scan/next 后完成文档和索引的绑定与读回，双重核验后 complete。写入结果不明先核对，不重复 create；读回失败复用已有 URL。状态与私人正文不得放回分享包。

当前宿主有真实定时工具就直接创建并核对；当前窗口没有能力时准备不含密钥的 CONTINUE.md，打开支持定时的入口续接，必要的本人步骤与两张官方图片整组发齐。宿主完全不支持时报告“定时尚未设置”，不把普通新聊天当作定时能力，不暗中安装系统服务。使用用户实际宿主的调度器，不创建属于制作者或其它产品的任务来冒充。

必须从宿主任务自身立即试跑新资料、核对飞书读回，再跑一次验证去重，读取真实任务详情、规则、时区与下一次时间后才登记回执、报告“自动同步已启用”。空跑、仅写本地配置、仅生成提示词或等待权限确认都不是启用验收。缺后台权限时说明影响并由用户本人决定，不自动开启全局完全访问。

模板字段和状态以 recording-rules.md 与 assets/feishu-template.json 为准。来源互动量与用户作品数据分开；看板跟随真实记录，不补造数据。

如需重启或中断，续接说明只含当前阶段、用户配置文件路径、已建测试文档 URL、固定任务目录和已登记任务 ID 及下一步，不含密钥、token、device_code 或授权链接；过期授权重新发起。
